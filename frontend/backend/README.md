# Travel Planner API

FastAPI + SQLAlchemy backend for the React travel planner. Local development uses SQLite by default. Set `DATABASE_URL` to a PostgreSQL connection string to use Supabase PostgreSQL.

## Run locally

```bash
cd backend
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload --port 8000
```

Open http://localhost:8000/docs for interactive API documentation and http://localhost:8000/api/v1/health to check the API/database.

## Endpoints

- `GET /api/v1/health`
- `GET /api/v1/trips`
- `POST /api/v1/trips`
- `GET /api/v1/trips/{trip_id}`
- `PATCH /api/v1/trips/{trip_id}`
- `DELETE /api/v1/trips/{trip_id}`
- `POST /api/v1/trips/{trip_id}/regenerate-day`

The request and response JSON use camelCase to match `src/types.ts` (for example `startDate`, `createdAt`, `dayNumber`). IDs are generated by the backend. The itinerary generator currently creates a starter template, not an AI-generated plan.

## Use Supabase PostgreSQL

1. Create a Supabase project and open **Project Settings → Database**.
2. Copy a PostgreSQL connection string. Use the direct connection if your environment supports IPv6; otherwise use the Supavisor session pooler connection. Replace credentials with your own and keep them private.
3. Put it in `backend/.env` as `DATABASE_URL=postgresql://...`. The app normalizes `postgresql://` to the `psycopg` SQLAlchemy driver and enables TLS only as requested by the connection URL; Supabase connection strings normally include the required SSL options.
4. Restart the API. Tables are created automatically for this MVP.

Never put database credentials in frontend `.env` files or variables prefixed with `VITE_`.

## Schema

The `trips` table stores trip preferences, dates, timestamps, and the itinerary JSON document. JSON is used for `interests` and `itinerary` so the nested day/activity structure can evolve without a migration for every itinerary field. For production, add Alembic migrations, authentication/user ownership, per-user authorization, and automated tests before public deployment.
